# 中文去 AI 腔清单（写完后逐条自检）

改编自 Sepia（https://github.com/Nanako0129/sepia，MIT）的中文校准与专业稿检查，针对中文科技内容重写，见 `credits.md`。

三条总原则：
- **不编造具体内容。** 删掉一句空话，比换上一个编出来的数字好。宁短勿假。
- **删除优先于添加。** 改稿时先删，删完读得通就不要补。
- **AI 腔是累积出来的。** 单独一处「同时」不是问题，一段三个才是。A 类见到就改，B 类数够了再改。

下面的例子用「X 公司」「产品 A」代替真实名称，只示范写法，不是事实，不要写进文章。

## A. 见到就改（禁用）

| 类别 | 词句 | 怎么改 |
|---|---|---|
| 开场套话 | 在当今……的时代、随着……的快速发展、近年来，……备受关注、众所周知、让我们一起来看看、今天给大家带来 | 删掉，第一句直接写最重要的事实 |
| 预告式开头 | 本文将探讨、下面我们来聊聊、本期为您带来 | 删掉，直接开始 |
| 定义式开头 | 「大模型是指……」「所谓 Agent，就是……」 | 读者不需要定义就删；需要就放到用到的地方 |
| 过渡套话 | 值得一提的是、值得注意的是、不难发现、毋庸置疑、不可否认、显而易见 | 删掉，句子直接接上 |
| 总结收尾 | 综上所述、总而言之、总的来说、总之、写在最后 | 删掉整段总结；最后一件事写完就停 |
| 展望口号 | 未来可期、让我们拭目以待、敬请期待、未来已来、开启新篇章 | 删掉；资料里有下一步计划就写计划本身 |
| 道德结尾 | 凸显了……的重要性、提醒我们……、这无疑……、具有重要意义 | 删掉；资料没说的意义不写 |
| 夸饰 | 重磅、炸裂、震撼、颠覆性、革命性、里程碑式、史诗级、王炸、遥遥领先、引爆、刷屏、火出圈、封神、天花板、杀疯了 | 换成具体数字或动作，或者直接删 |
| 空话 | 赋能、助力、全方位、多维度、深度融合、持续发力、注入新动能、迈出了重要一步、打造……生态 | 写清楚到底做了什么 |
| 聊天机器人残留 | 作为一个 AI、以下是改写后的……、希望对你有帮助、如有疑问、好的，我来…… | 删掉，只输出正文 |
| 极限词（小红书尤其） | 全网最、史上最、第一、唯一、顶级、100%、绝绝子、yyds、闭眼入、无脑冲、必入 | 删掉；「首个」「最快」只能写成「X 公司称……」，标题里不用 |

## B. 数一数（堆起来才是问题）

| 模式 | 上限 | 例子 → 改法 |
|---|---|---|
| 「不是……而是……」 | 全文 1 次，且要纠正一个真实存在的误解 | 「这不是一次升级，而是一次重构」→ 「产品 A 的推理部分重写了」 |
| 连接词：此外、同时、然而、另外、与此同时、因此、并且、以及 | 每段最多 1 个，全文最多 3 个 | 上下文已经连贯就删，让两句并排 |
| 说话动词前的「X 地」 | 0 | 「兴奋地表示」→「说」 |
| 引述动词轮换：表示、指出、强调、坦言、透露 | 默认用「说」；「坦言」全文最多 1 次 | 「X 公司 CEO 强调」→「X 公司 CEO 说」 |
| 虚化动词：进行、加以、予以、作出 + 名词 | 尽量 0 | 「进行优化」→「优化」；「作出决定」→「决定」 |
| 名词化主语：○○性、○○化、○○感 | 一段最多 1 个 | 「安全性得到了提升」→「更安全了：误拒率从 a% 降到 b%」（数字必须来自资料） |
| 程度副词：非常、十分、极其、显著、大幅 | 一段最多 1 个；能用数字就不用 | 「大幅降价」→「降价 60%」（资料里有才写） |
| 三项排比、「从 A 到 B，从 C 到 D」、对仗句 | 全文 1 处 | 拆开，或只留最重要的一项 |
| 段首「其实」「事实上」「说白了」 | 0 | 删掉 |
| 给抽象词加引号：「趋势」「关键」「新范式」 | 0 | 去掉引号，或换成具体说法 |
| 自问自答：「这意味着什么？答案是……」 | 0 | 直接写答案；资料没给答案就删问句 |
| 对读者说话：「你会发现」「我们可以看到」 | 0（小红书可以用「你」，但不说「你会发现」） | 删掉主语，直接陈述 |
| 「某某表示：『……』」 | 不要每条引语都这个格式 | 引语可以放句首，也可以只转述 |
| 没有参照的数字 | 0 | 「提升到 72%」后面补上资料里的对比对象（上一版、对手）；资料没有就不写「提升」 |

## C. 结构

- **开头：** 第一句就是最重要的那件事（谁、做了什么、关键数字）。不铺背景，不写「近日」「日前」开头的套话。
- **标题与小标题：** 概括这一节的结论（「价格降到上一代的一半」），不写分类词（「价格方面」）。小标题下第一句不要把小标题再说一遍。
- **不要分形总结：** 不在每节开头预告、结尾再总结一遍；全文也不要最后总结一遍。
- **格式装饰：** 不用「**加粗短语：**」当段首小标题；不用装饰性 emoji（小红书除外，且有上限）；不要把什么都写成三条。
- **段落：** 长短交错。允许一个长句（用逗号串起几层信息）后面接一个短句；不要连着三句差不多长，也不要每段都一样长。
- **结尾：** 停在一个具体的事实上：下一步时间、还没公布的信息、可以去哪里用。不要升华，不要号召，不要「欢迎关注」「点赞在看」。

## D. 事实

- 每个数字、日期、金额、版本号都能在 `<summary n>` 里找到，逐字照抄，不换算、不四舍五入、不加「约」。
- 引语只用资料里的原话；英文引语译成中文时意思不能变，不要加料。
- 资料没写的原因、影响、评价、行业意义、「业内人士认为」一律不写。
- 标了 `full_text="false"` 的条目只写确定的部分，必要时写「原文未说明」。
- 不同条目的事实不要串：A 条的数字不能出现在 B 条的句子里。

## E. 人写的中文是什么样（语域允许时）

- 单音节动词：用、看、改、砍、涨、降、发（「使用」「进行发布」改成「用」「发布」）。
- 主语承前省略：同一个主语连续出现时，后面的句子不必再写一次。
- 引述用「说」；能直接陈述的不用引述。
- 中文标点全角；英文、数字、产品名两侧空格跟随输入；引号用 “ ”；省略号「……」、破折号「——」都少用。
- 英文资料译成自然的中文，产品名、模型名、人名、代码保留原文。

## F. 自检步骤（输出前做完，不要把自检过程写进输出）

1. **事实对照：** 逐句问「这句的依据在哪条 `<summary>` 里？」找不到就删或改回原话。
2. **删除测试：** 逐句问「删掉这句，读者会少知道什么吗？」不会就删。
3. **A 类扫描：** 把上面 A 表的词句在稿子里找一遍，见到就改。
4. **B 类计数：** 数「不是……而是」、连接词、「X 地」、虚化动词、程度副词，超过上限就删到上限以内。
5. **结构检查：** 开头是不是事实？小标题是不是结论？结尾有没有总结、展望或号召？
6. **平台硬指标：** 按本 Skill 的平台规则核对字数、条数、标签数、链接与封面行。
7. **读一遍节奏：** 有没有连续三句一样长、三段一样长？有就合并或拆开一处。
